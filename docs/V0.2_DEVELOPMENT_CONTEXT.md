# MediPrompt v0.2 - Development context

**Status:** Implemented and security-reviewed first-playable contract

**Target branch:** `feature/v0.2-first-playable` (branch from latest `develop` only)

**Baseline date:** 2026-08-30

**Purpose:** single, minimum-context entry point for whoever writes or reviews the v0.2 code. It consolidates the normative v0.2 requirements from the design baseline into one actionable brief. Where this file and a design file disagree, the design file (`EXECUTION_PLAN.md`, `L4_CODE_DESIGN.md`, `DIFFICULTY_AND_DEPTH_DESIGN.md`) is authoritative.

## 1. What v0.2 is

A static TypeScript PWA that delivers the compact Unprompted-style medical speaking-practice tool with **no account, no microphone, no model download, no backend, and no persistent storage requirement**. Speech intelligence, feedback, scheduling, Spring Boot, and connected AI are explicitly out of scope and remain progressive enhancements for later versions.

The non-negotiable product invariant (from `IMPLEMENTATION_HANDOFF.md`):

```text
choose mode + challenge + subject -> spin -> see topic -> timed speech -> finish/exit -> repeat
```

This path must keep working with microphone, model, storage, and network all unavailable. Every later version is additive and must not break this contract.

## 2. What is explicitly excluded from v0.2

Do not add any of the following — they belong to v0.3+ and their presence in v0.2 is scope creep:

- Microphone permission, recording, playback, Web Audio, VAD.
- `whisper-base.en` or any STT worker; transcript review/correction UI.
- Embeddings, rubric coverage matching, prescriptions, Refinement Delta, retry comparison.
- Viva follow-ups, evidence updates, scheduling, spaced queue, history/export/delete.
- Login, accounts, PostgreSQL, Spring Boot, REST API, provider adapters.
- PDF ingestion, content compiler, authoring-inventory validation.

## 4. TypeScript contracts to implement in v0.2

Implement only the subset of `L4_CODE_DESIGN.md` §2 needed for the first-playable loop. Required types:

```ts
type PracticeMode = "RECALL_SPRINT" | "VIVA_ROUND" | "DEEP_RESEARCH" | "TEACH_BACK";
type V02PracticeMode = Extract<PracticeMode, "RECALL_SPRINT" | "DEEP_RESEARCH">;
type ChallengePreset = "GUIDED" | "APPLIED" | "VIVA";
type Register = "EXAMINER" | "JUNIOR" | "PATIENT";
type SupportLevel = "FULL" | "FADING" | "MINIMAL";

interface TopicRef {
  packId: string; packVersion: string; subjectId: string; topicId: string;
  variantId: string; difficultyProfileVersion: string; promptId: string; rubricId: string;
}

interface TimePolicy { preparationSeconds?: number; speakingSeconds: number; researchSeconds?: number; }
interface SpeechArcStep { id: string; label: string; }
interface UserSettings { schemaVersion: 1; speakingSeconds: number; researchSeconds: number; }
interface PracticeSelection { mode: V02PracticeMode; challenge: ChallengePreset; subjectId: string; register?: Register; }
interface SettingsStore { load(): UserSettings; save(s: UserSettings): void; clear(): void; }
interface BagState {
  eligibleVariantIds: readonly string[];
  remainingVariantIds: readonly string[];
}
interface BagStore {
  load(fingerprint: string): BagState | undefined;
  save(fingerprint: string, state: BagState): void;
  clear(): void;
}
interface PracticeSession {
  id: string; topic: TopicRef; mode: V02PracticeMode; challenge: ChallengePreset;
  supportLevel: SupportLevel; register?: Register; timePolicy: TimePolicy;
  attemptIds: string[]; createdAt: string; completedAt?: string;
}
```

From `DIFFICULTY_AND_DEPTH_DESIGN.md` §10, also carry `ChallengeIdentity`:

```ts
interface ChallengeIdentity {
  preset: ChallengePreset; difficultyProfileVersion: string; variantId: string; supportLevel: SupportLevel;
}
```

`ChallengeIdentity` joins topic/mode/register/rubric/time-policy/pack identity in the in-memory
`TopicSnapshot` and `AttemptDraft`. v0.2 does not persist sessions or attempts. Threshold/model
identity starts with the features that actually use it; do not create placeholder values.
Effective accessibility durations are frozen into that topic/attempt snapshot when a topic is
drawn. A settings change after the draw applies to the next topic, never an active attempt.

`VIVA_ROUND` and `TEACH_BACK` remain reserved domain values for later versions. They are not
selectable, rendered, routed, or accepted as v0.2 session input. The narrower `V02PracticeMode`
type prevents dead controls and unreachable state.

v0.2 has no register selector: validated content defaults to `EXAMINER`. It also defaults to `FULL`
support and changes support only when the chosen variant contains a reviewed scaffold. Keeping the
dimensions distinct in data does not authorize placeholder UI.

Rules that apply now:
- Accessibility time adjustments must not change `ChallengePreset`.
- `LocalStorageSettingsStore` treats browser storage as untrusted. It owns one namespaced,
  schema-validated JSON value, accepts only an own-property object with the exact expected keys,
  clamps finite durations to documented bounds, and falls back to immutable in-memory defaults on
  denied access, malformed JSON, quota errors, or an unsupported/newer schema. Never recursively
  merge parsed data. It contains no transcript, audio, attempt, account, bag, or medical-learning
  data. `clear()` participates in the future delete-all workflow.

Types deliberately deferred (`TranscriptDraft`, `ApprovedTranscript`, `DeliveryMetrics`, `ConceptEvidence`, `CoverageResult`, `Prescription`) are not implemented in v0.2. Do not stub them in the learner app.

## 5. Session reducer scope

Implement `reduceSession(state, event)` as a **pure** function (`L4_CODE_DESIGN.md` §3). Effects are returned as commands and run by an orchestrator; every async command carries `sessionId`, `attemptId`, and `requestId`, and late responses that do not match current state are ignored.

v0.2 implements this slice of the state machine:

- **Recall Sprint:** `IDLE → DRAWING → TOPIC_READY → SPEAKING → ATTEMPT_COMPLETE`.
- **Deep Research:** inserts `RESEARCHING → READY_TO_SPEAK` before `SPEAKING` (drawn topic → research countdown → `Done researching` → `Ready to speak` confirmation → speaking timer).

Invariants to enforce in the reducer:
- `START_TIMER` and `START_RESEARCH` are invalid until `TOPIC_DRAWN` for the current `requestId` has succeeded (timer action is disabled until a topic is drawn — this is an exit-gate requirement).
- `SPIN_AGAIN` returns from `ATTEMPT_COMPLETE` (or closed timer) back to `DRAWING`.
- Clocks (monotonic for active timers, wall-clock ISO for in-memory session metadata) are injected,
  not read directly, so tests control time.
- A stale `TOPIC_DRAWN`, timer completion, or visibility event with a non-current request/session
  identity is ignored.
- Durations and content-derived events are validated before entering the reducer. Exhaustive event
  handling returns the current state for invalid transitions and never manufactures a topic.

Do not define or stub states past `ATTEMPT_COMPLETE` (`PROCESSING`, `TRANSCRIPT_REVIEW`,
`SELF_REVIEW`, `REVIEW`, `SCHEDULING`, `COMPLETE`) in the v0.2 implementation. They add untested
surface area and arrive with their owning versions.

## 6. Algorithms to implement

### Deadline timer (`L4` §4)

```text
start(now, duration) => deadline = now + duration
remaining(now)       => max(0, deadline - now)
tick                 => render remaining(current monotonic time)
visibility restored  => recompute; emit deadline event once when remaining == 0
```

The speaking and Deep Research timers must survive background/foreground transitions (an exit-gate
item). Use a monotonic clock inside an active timer and recompute on visibility restore. Validate
all durations as finite integers within documented bounds before computing a deadline; reject
negative, `NaN`, infinite, and overflowing input. The deadline event is idempotent and fires once.
Wall-clock ISO timestamps are used only as in-memory metadata in v0.2. Tests inject both clocks.

### Non-repeating random draw (`L4` §4)

1. Build sorted eligible **variant IDs** and a canonical filter fingerprint (all pack IDs/versions,
   subject, challenge, implemented mode and register when it changes eligibility).
2. Load the remaining shuffled bag for that fingerprint from an injected `BagStore`; v0.2 uses an
   in-memory implementation only.
3. Treat bag state as untrusted even behind the port: remove duplicates and unknown IDs. If the
   candidate set changed, intersect the bag and append/shuffle newly eligible IDs.
4. If empty, Fisher–Yates shuffle all candidates with an injectable random source.
5. Move a recently drawn ID to the end when at least two alternatives exist.
6. Pop one ID and store the remaining bag in memory.

Deterministic seeded randomness is used in tests. Production uses an unbiased Fisher-Yates index
derived from `crypto.getRandomValues`; if the Web Crypto API is unavailable, fail visibly to a
reviewable deterministic choice rather than silently using `Math.random`. Changing
challenge/subject/mode updates eligible variants and resets the shuffled-bag fingerprint. Bags do
not repeat variants before exhaustion for the full fingerprint (`DIFFICULTY` §13 product-behavior
test).

## 7. Runtime topic-pack schema

Author the normative schema at `content/schema/topic-pack.schema.json` per `L4` §5 restrictions: `additionalProperties: false`, semantic pack versions, valid locale, unique stable IDs, versioned challenge profiles, bounded timer values, non-empty original wording, resolvable source references, allowed review statuses, and **no runtime publication when status is not `APPROVED`**.

An unattested `DRAFT` uses `reviewers: []` and `reviewedAt: null`; only `APPROVED` requires a
non-empty reviewer list and review date. This prevents placeholder identities and fabricated review
dates while keeping a structurally valid candidate available for actual review.

Minimum runtime shape (full example in `L4` §5):

```json
{
  "schemaVersion": "1.0", "contentKind": "MEDICAL",
  "packId": "demo-foundations", "version": "1.0.0",
  "title": "Medical Foundations Demo", "locale": "en-IN",
  "licence": { "id": "CC-BY-4.0", "attribution": "..." },
  "review": { "status": "APPROVED", "reviewers": [{ "id": "reviewer-id", "role": "MEDICAL_REVIEWER" }], "reviewedAt": "2026-08-30" },
  "sources": [{ "sourceId": "src-1", "citation": "...", "url": "https://...", "accessedAt": "2026-08-30" }],
  "subjects": [{ "subjectId": "physiology", "title": "Physiology", "topics": [ { ... } ] }]
}
```

Per-topic variant contract (`DIFFICULTY` §10): each variant carries `variantId`,
`challengePreset`, `difficultyProfileVersion`, `blueprint`, `promptId`, `mode`, `supportLevel`,
`wording` (educator-authored text), `answerArc`, `timePolicy`, `caseRef`, `followUpRefs`, and
`rubricId`. Validator rules reject identical prompt variants that claim greater difficulty only
through a shorter timer.

### Untrusted-content boundary

- Validate source YAML during generation, generated JSON in CI, and parsed JSON again before
  activation in the browser. A failed/newer pack never partially activates; continue with the
  previous bundled valid pack or a small compiled fallback.
- Parse authoring YAML with a safe loader: disable arbitrary type construction and custom tags,
  reject aliases, duplicate mapping keys and multi-document input, and enforce input/depth limits
  before schema validation. Compilation never resolves URLs or executes pack-provided values.
- Enforce byte, collection, string-length, timer, nesting, and identifier limits in addition to
  JSON Schema. Custom checks enforce uniqueness and all cross-references.
- Treat all titles, wording, arcs, attribution and citations as plain text. React escaping is the
  rendering boundary: prohibit `dangerouslySetInnerHTML`, runtime Markdown/HTML rendering, dynamic
  code, inline event handlers, and pack-provided CSS/class names.
- Reject dangerous object keys (`__proto__`, `prototype`, `constructor`) and build domain objects
  explicitly; do not spread or recursively merge parsed pack objects.
- If source links are rendered, allow only reviewed `https:` URLs, open them with
  `rel="noopener noreferrer"`, and never derive script/image/module URLs from pack content.
- Freeze or deeply copy validated domain objects so later UI code cannot mutate the active pack.
- The reference-only curriculum YAML is never imported by application code, copied into public
  assets, or accepted as a runtime fallback.

## 8. Demo content pack requirements

Ship **one hand-authored demo pack**. Minimums from the execution plan and handoff:

- At least **20 topics**, each with at least one **Guided** variant.
- At least **three complete Guided/Applied/Viva trios** to validate the selector and schema. Applied variants require a reviewed fictional case and a decision link; Viva variants additionally require plausible alternatives and a reviewed follow-up or evidence update.
- The challenge selector is **hidden** when the selected content has only one eligible preset. A single-variant pack silently uses `GUIDED`. Disabled fake choices are worse than a smaller honest interface.
- Topics with only a Guided variant still draw and run; the loop never breaks because Applied/Viva is absent.

Content provenance rules (non-negotiable):
- No generated or unsourced medical ground truth. No copied source prose. No real patient identifiers.
- Rubrics, prompts, and cases must be educator-authored. The curriculum file under `docs/curriculum/` is a `DRAFT`, `REFERENCE_ONLY`, `runtimeCompatible: false` authoring inventory — do not load it as a runtime pack.
- Open decision (do not invent): the named medical educator reviewer and the final
  software/content licence. Do not fabricate reviewer identity, approval date, attribution, source,
  or licence metadata and do not self-mark a pack `APPROVED` to make CI pass.
- While approval is pending, implementation and tests may use an unmistakably synthetic
  `NOT_FOR_PUBLICATION` fixture that the production build rejects. The v0.2 exit gate and GitHub
  Pages artifact still require a genuinely approved demo pack or a separately approved
  non-medical interaction fixture; release must not quietly publish draft medical content.
- Runtime packs declare `contentKind`. An `APPROVED` medical pack requires a
  `MEDICAL_REVIEWER`; a `CONTENT_EDITOR` may approve only the explicitly non-medical interaction
  fixture. v0.2 keeps support at `FULL` until a reviewed scaffold contract exists.
- Compile JSON Schema validation to committed standalone code and verify generated-code drift in
  CI. Do not permit runtime schema compilation or weaken CSP with `unsafe-eval`.

Implemented medical candidate:

- `content/candidates/mpt-cardiorespiratory-review-candidate.json` contains 20 MPT
  cardiovascular/respiratory topics, 46 source-linked rubrics, two modes, and three complete
  challenge trios.
- `docs/curriculum/MPT-CARDIORESPIRATORY-SOURCE-REVIEW.md` records exact curriculum coordinates,
  the source-currency/access register, narrow claim scope, and reviewer attestation template.
- Candidate validation rejects generator drift and requires `MEDICAL`, `DRAFT`, no attestation,
  minimum depth, production-gate rejection, and a matching filename.
- It is never copied into `public/` or `dist/`; the approved non-medical interaction fixture stays
  active until an identified educator reviews the exact candidate.

## 9. UI behavior

Compact one-screen practice surface (`DIFFICULTY` §11):

```text
Practice mode  [Recall] [Research]
Challenge      [Easy · Guided] [Medium · Applied] [Hard · Viva]
Subject        [selected subject]
                         [Spin]
```

- Only Recall Sprint and Deep Research are rendered in v0.2. Do not show disabled or placeholder
  Viva Round/Teach-back controls. Mode and challenge remain independent; changing either updates
  eligible variants and resets the shuffled-bag fingerprint.
- The **Spin** action shows a visible drawing state and supports **Spin again**.
- The timer action is disabled until a topic has been drawn.
- Recall Sprint goes directly from drawn topic to the speaking timer.
- Deep Research goes drawn topic → research countdown → `Done researching` → `Ready to speak` → same speaking timer.
- The speaking view is distraction-free: topic, three-step medical answer arc, large circular countdown, current instruction, and a close/end action. Topic card shows a one-line expectation (e.g. "Explain core ideas"), not a threatening badge.
- A settings surface exposes speech and research durations; settings persist locally when storage is available and fall back to defaults otherwise.
- Color is never the sole signal. Avoid green/easy and red/hard as ability judgments. v0.2 uses the
  reviewed answer arc as its support. Show `Need a scaffold` only when a reviewed scaffold exists;
  do not create a dead control or persist fake support-use history. Richer rescue scaffolding starts
  with its owning version.
- Completion or close returns to spin again.

## 10. Accessibility (v0.2 baseline, from `L4` §8)

- One `<main>` landmark and one page heading; native buttons and form fields.
- Move focus to the state heading after deliberate transitions, not every timer tick.
- `aria-live="polite"` for processing completion and significant timer thresholds; never a per-second countdown announcement.
- Pair the timer visual with text. Minimum touch target about 44 × 44 CSS pixels where controls do not overlap.
- Respect `prefers-reduced-motion`; no looping/pulsing animation required.
- Test at 320px width, 200% zoom, keyboard only, screen-reader smoke, and speech-recognition-off.

## 11. Offline shell and hosting

- Static PWA deployable to GitHub Pages; zero recurring app cost.
- Configure the application, manifest, router and service-worker scope for the repository base path;
  never assume deployment at `/`.
- The install step precaches only a fixed, build-generated manifest of same-origin hashed assets and
  the approved runtime pack. Installation is atomic: a failed fetch/validation keeps the previous
  cache usable.
- Fetch handling accepts only same-origin `GET` requests. Never cache `POST`, range, cross-origin,
  opaque, redirected-to-another-origin, error, or extension requests.
- Use network-first with a cached fallback for HTML navigations and cache-first for immutable hashed
  assets. Validate a pack before activation; an invalid update cannot replace the last valid pack.
- Cache names use an application-owned prefix plus build/pack version. Activation deletes only
  older caches with that exact prefix, never every origin cache. Avoid an automatic mid-session
  takeover that mixes old HTML with new assets; prompt for refresh when a new worker is ready.
- The complete mode/challenge/subject -> spin -> timed-speech flow works after a successful first
  load with the network disabled. v0.2 has no model assets, runtime CDN, analytics, remote fonts, or
  third-party scripts.
- If the separately cached full pack is missing, oversized, redirected, or invalid, activate the
  small compiled and reviewed non-medical fallback. Show that fallback state to the learner; never
  turn a pack failure into a blank or fabricated topic.

## 12. Security and supply-chain baseline

### Browser policy

- Ship no secrets. A static bundle, source map, runtime JSON, service worker, environment variable,
  or GitHub Pages artifact is public. Fail the build if a client-prefixed environment variable is
  treated as private.
- Use no remote executable code, CDN scripts, analytics, trackers, external fonts, or third-party
  frames. Do not use `eval`, `new Function`, string timers, `document.write`, or
  `dangerouslySetInnerHTML`.
- Set the strictest practical CSP in the HTML (`default-src 'self'; script-src 'self'; style-src
  'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; worker-src 'self'; manifest-src
  'self'; object-src 'none'; base-uri 'self'; form-action 'none'`). Keep scripts/styles external so
  `unsafe-inline` is unnecessary. Automated browser tests assert prohibited outbound requests fail.
- GitHub Pages cannot provide every custom response header. Record that limitation; do not claim
  `frame-ancestors`, HSTS, COOP/COEP or other header-only protections unless deployment evidence
  proves them. The app carries no authentication or sensitive server state in v0.2.
- Render pack and localStorage values as text only. Never place them in raw HTML, CSS, module paths,
  storage keys, telemetry, or navigation without allowlist validation.

### Repository and CI policy

- Pin Node and pnpm major/exact CI versions, commit the lockfile, and install with
  `pnpm install --frozen-lockfile`. Minimize dependencies and document why every runtime package is
  required.
- Pin third-party GitHub Actions to immutable commit SHAs. Give each job explicit least privilege;
  normal validation needs only `contents: read`.
- Never use `pull_request_target` to build or execute contributor code. Pull requests build/test
  without write tokens or production environments. A Pages deployment runs only from a protected,
  reviewed branch and uploads the artifact produced from that exact checked-out commit.
- Do not interpolate branch names, PR titles/bodies, changed filenames, or issue text into shell
  commands. Do not download and execute unverified tools during CI.
- Add dependency review, secret scanning/pattern checks, lockfile review, and a production-bundle
  inventory. Audit findings are triaged by exploitability; audit output alone neither proves safety
  nor justifies an unreviewed upgrade.
- Exclude editor files, local environment files, test reports with paths/content, caches, and build
  output from Git. Production source maps are either intentionally public and reviewed or omitted;
  they never contain secrets.

## 13. Tests and exit gate

Required test kinds (from the handoff and `L4` §11 acceptance map):

- **Unit:** pure session reducer transitions (Recall and Deep Research paths), stale-event rejection,
  bounded/idempotent deadline timer with injected clocks, shuffled-bag draw (determinism,
  no-repeat-before-exhaustion, corrupt-state cleanup, fingerprint reset, single-eligible fallback),
  and settings store with denied/malformed/newer-schema/quota fallback.
- **Content/property:** reject unsafe YAML tags/aliases/duplicate keys, unknown fields, dangerous
  object keys, duplicate IDs, dangling references, excessive sizes/depth, invalid URLs, invalid
  timers, draft packs, and unsupported schema versions; render adversarial strings as inert text.
- **Component:** mode/challenge/subject controls independent; challenge selector hidden for
  single-eligible content; unsupported Viva Round/Teach-back controls absent; Spin and Spin again;
  timer disabled before draw.
- **Accessibility smoke:** 320px, 200% zoom, keyboard only, screen-reader, reduced motion.
- **Mobile viewport:** render and interact at phone widths.
- **Background timer:** timer survives background/foreground and emits the deadline event once.
- **No-capability:** the full loop runs with microphone, storage, model, and network capabilities disabled.
- **Service worker/e2e:** production build works under the GitHub repository subpath; only approved
  same-origin GET assets are cached; failed install/update preserves the prior shell/pack; activation
  deletes only owned caches; offline reload completes the core loop.
- **Security/CI:** CSP blocks unexpected outbound/script/frame requests; built assets contain no
  secret fixtures or draft curriculum; workflow tests/checks enforce pinned actions, explicit
  permissions, frozen lockfile, no `pull_request_target`, and no PR deployment credentials.

CI commands to make executable in v0.2 (`L4` §10): `pnpm lint`, `pnpm typecheck`, `pnpm test`,
`pnpm test:a11y`, `pnpm test:e2e`, `pnpm content:validate`, and `pnpm build`. CI uses pinned Node,
restores caches by lockfile hash, installs frozen, and builds/tests the production artifact from a
clean checkout.

**v0.2 exit gate** (`EXECUTION_PLAN.md` §3): a first-time phone user can infer the mode/challenge/subject → Spin → Start timer flow, reaches a topic in under five seconds, and completes or exits a timed attempt without instructions. Challenge, mode, register, support, and accessibility time remain independent. The basic tool still works with microphone, storage, model, and network capabilities disabled. Unit, component, accessibility-smoke, and mobile-viewport tests pass. No secret, raw audio, transcript, or patient data is committed or logged (trivially satisfied in v0.2 since none exist yet, but the invariant holds).
