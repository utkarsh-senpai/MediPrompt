# MediPrompt v0.3 Development Context — Private Speech Intelligence

Status: build brief for the next version. Consolidates the v0.3 scope from the design docs into
one executable contract, the same way `V0.2_DEVELOPMENT_CONTEXT.md` did for the first playable.
Base: `main` at PR #10 (v0.2 first playable + source-grounded MPT review candidate).
Planned branch: `feature/v0.3-private-speech`.

This brief is the single source of truth for v0.3 implementation. If code and this brief disagree,
the brief wins until it is amended.

## 1. What v0.3 is

v0.3 turns the v0.2 timed attempt into a *measured* attempt, entirely on-device:

- Microphone permission with a permission primer and full failure handling.
- Local WebM recording of the speaking window, with in-app playback.
- Web Audio delivery measurements and voice-activity detection: duration, WPM, fillers,
  repetition, silence, pauses, loudness variation, clipping.
- Lazy, cancellable, cached, browser-local `whisper-base.en` transcription worker.
- Transcript review and correction before any downstream use of the text.
- Explicit unsupported-device and low-memory fallbacks.

The v0.2 loop (mode/challenge/subject → spin → timed speech → attempt complete) is unchanged.
Everything v0.3 adds is an optional post-attempt extension: a learner on a device without a
microphone, or who denies permission, gets the full v0.2 experience plus typed/self review.

## 2. What is explicitly excluded

- Content coverage, concept evidence, scoring, prescriptions (`ConceptEvidence`,
  `CoverageResult`, `Prescription`): v0.4. v0.3 shows delivery observations **separately** from
  any content judgment; the transcript is never auto-scored.
- Emotion recognition, confidence inference, accent modification, always-on microphone
  monitoring, voice identity or biometrics of any kind (L1 non-goals, contractual).
- Raw audio leaving the browser. No upload, no telemetry payload containing audio or transcript.
  This is an exit-gate item, not a preference.
- Web Speech API as the dependable transcription path. It may be added later as an enhancement;
  typed/corrected transcripts and local Whisper are the contractual paths.
- Auto-correction of medical meaning in transcripts, and any score shown before the learner
  approves a transcript.
- Comparing absolute loudness across devices.
- Draft-pack (medical candidate) activation. That mechanism is a separate controlled-beta track
  (see §9); v0.3 ships against the same non-medical production fixture as v0.2.
- Accounts, backend, server storage: still out.

## 3. Repository scaffold additions

Existing v0.2 structure is untouched except where listed. New modules under
`apps/learner-web/src/`:

- `audio/` — `recorder.ts` (permission, MediaRecorder lifecycle, playback-URL lifetime),
  `pcmDecode.ts` (WebM → mono float PCM), `vad.ts`, `deliveryMetrics.ts`, `audioErrors.ts`.
- `speech/` — `transcriptionClient.ts` (worker protocol: load progress, cancel, timeout,
  stale-response drop), `transcribe.worker.ts` (lazy pinned model, WASM/runtime adapter).
- `practice/` — reducer extended with the post-attempt states in §5; `usePracticeSession`
  extended to drain the new commands. No changes to existing v0.2 events' semantics.
- `components/` — `MicPrimer.tsx`, `RecordingIndicator.tsx`, `PlaybackBar.tsx`,
  `TranscriptEditor.tsx`, `DeliveryPanel.tsx`, `ProcessingView.tsx`.
- `src/test/fixtures/pcm/` — synthetic PCM fixtures (sine, silence, clipping, speech-like bursts)
  plus the generation script, mirroring `scripts/generate-demo-pack.ts`.
- Model assets: pinned whisper build served same-origin from `public/models/` (or fetched once
  from a pinned, integrity-checked artifact and cached — see §12). Never a remote `<script>`.

## 4. TypeScript contracts to implement

Verbatim from L4; these shapes are contractual.

```ts
interface TranscriptDraft {
  text: string;
  source: "LOCAL_WHISPER" | "WEB_SPEECH" | "TYPED";
  model?: { id: string; version: string; quantization: string };
  uncertainRanges: Array<{ start: number; end: number }>;
}

interface ApprovedTranscript {
  rawText?: string;
  text: string;
  approvedAt: string;
  wasEdited: boolean;
}

interface DeliveryMetrics {
  durationMs: number;
  spokenMs?: number;
  wordsPerMinute?: number;
  fillerCount?: number;
  repeatedPhraseCount?: number;
  pauses: Array<{ startMs: number; durationMs: number; kind: "MID_CLAUSE" | "BOUNDARY" | "UNKNOWN" }>;
  clippingRatio?: number;
  loudnessVariationDb?: number;
  limitations: string[];
}
```

Rules:

- Every optional field absent means "not measurable on this device/recording", never "zero".
- `limitations` is mandatory and human-readable (e.g. `"loudness uncalibrated on this device"`).
- Only `ApprovedTranscript.text` flows downstream. `rawText` is retained only so the learner can
  compare; it is never scored in v0.3.
- Audio/decode/VAD/recorder failures use `AUDIO_*` error codes from `audioErrors.ts`; each code
  maps to one row of the error matrix in §5.
- All async results (worker messages, decode promises) carry the attempt's `requestId`; stale
  results are dropped exactly like stale v0.2 draw events.

## 5. Session reducer scope

New states, all post-`ATTEMPT_COMPLETE` and all optional extensions:

```
ATTEMPT_COMPLETE --RECORDING_READY--> PROCESSING
PROCESSING       --METRICS_READY + TRANSCRIPT_READY--> TRANSCRIPT_REVIEW
PROCESSING       --TRANSCRIPTION_UNAVAILABLE---------> SELF_REVIEW   (typed/self path)
TRANSCRIPT_REVIEW--TRANSCRIPT_APPROVED----------------> REVIEW
SELF_REVIEW      --SELF_REVIEW_DONE-------------------> REVIEW
REVIEW           --SPIN_AGAIN / EXIT------------------> (v0.2 exits)
```

Invariants:

- Removing every v0.3 state and command must leave the v0.2 reducer paths byte-for-byte
  behaviorally identical. v0.3 is an extension, not a rewrite; v0.2 tests keep passing unchanged.
- `TRANSCRIPTION_UNAVAILABLE` is a first-class outcome (mic denied after the fact, unsupported
  codec, model download offline, low memory, timeout). An absent transcript is a valid result,
  never hidden behind a fabricated one.
- Recording arms only with the speaking window: permission primer before first arm; if denied or
  unavailable, `SPEAKING` continues timer-only and **no audio object is created at all**.
- Editing the transcript never changes audio-derived metrics. `TRANSCRIPT_APPROVED` carries the
  `ApprovedTranscript`; metrics were already final at `METRICS_READY`.
- The reducer stays pure: audio devices, decoders, and the worker are injected dependencies,
  clock-injected like the v0.2 deadline timer.

Error matrix (each row has a reducer transition + a UI copy row + a test):

| Failure | Behavior |
| --- | --- |
| Mic denied | Continue with timer + self/typed review; no audio created |
| Unsupported codec | Timer-only path; no partial blob kept |
| Model download offline | Continue without transcription; offer retry later |
| Low memory / worker timeout | Cancel cleanly; worker state released |
| Uncertain transcript | Highlight uncertain spans; nothing scored until approved |

## 6. Algorithms to implement

All measurement code is pure functions over mono float PCM + a sample rate, unit-testable with
synthetic fixtures. Deterministic within documented tolerances (exit gate).

- **Decode**: WebM blob → mono `Float32Array` PCM. Decode failures are `AUDIO_DECODE_*`.
- **VAD**: energy-based speech/silence intervals with calibrated minimum speech/silence
  durations; output is intervals, not interpretations.
- **Pauses**: a pause is a non-speech interval bounded by speech on both sides, above the
  calibrated minimum, below the terminal-silence limit. `kind` is `MID_CLAUSE`/`BOUNDARY` only
  when transcript timestamps and punctuation align; otherwise `UNKNOWN`. Never guess.
- **WPM**: `approvedTranscriptWordCount / (spokenMs / 60000)`. Computed only after transcript
  approval; absent without it.
- **Fillers**: locale/pack-aware token patterns matched against the approved transcript's
  evidence spans; count reported, list shown in review UI.
- **Repetition**: repeated-phrase count over the approved transcript.
- **Clipping ratio**: samples at/near full-scale ÷ all samples, with fixture-pinned thresholds.
- **Loudness variation (dB)**: conservative calibration; variation within one recording only.
  Absolute loudness is never compared across devices; when uncalibrated, say so in
  `limitations`.
- **Recording retention**: the recording exists only for in-app playback; the blob and its
  object URL are revoked on attempt discard, spin-again, or navigation. Nothing persists across
  reloads in v0.3.

## 7. Recording and transcription worker

- **Permission primer before request** (UJ2): the app explains microphone use and local-only
  processing in plain language *before* the browser prompt. The primer is shown once per
  session at first arm, not on page load.
- **Recorder**: wraps `getUserMedia` + `MediaRecorder`; explicit states
  (idle → primed → recording → finalizing → ready/failed); playback URL lifetime owned by the
  recorder module; capability detection feeds the existing capability line.
- **Transcription worker**: lazy-loaded only after explicit learner activation ("Transcribe my
  attempt"); pinned `whisper-base.en` build; download progress, cancellation, timeout, and
  low-memory errors are all visible and recoverable; worker is terminated and its memory
  released on cancel/timeout; model metadata (`id`, `version`, `quantization`) is recorded in
  every `TranscriptDraft`.
- The worker speaks a versioned message protocol; unit tests cover load progress, cancellation,
  stale-response drops, memory-failure, and pinned-version verification.

## 8. Transcript review and correction

- Raw transcript is shown as inert text (same untrusted-content rule as v0.2 pack wording).
- Low-confidence spans from `uncertainRanges` are highlighted; the UI never auto-corrects
  medical meaning.
- Corrections are explicit learner edits; saving produces the `ApprovedTranscript`
  (`wasEdited`, `approvedAt`).
- The typed path (`source: "TYPED"`) is always available, including when transcription worked —
  the learner may prefer typing.

## 9. Content and data policy

- Runtime pack unchanged: the non-medical `demo-interaction-fixture` remains the only production
  pack. The MPT candidate stays in the `content/candidates/` lane as unattested `DRAFT`.
- Per the pre-attestation testing policy (`docs/PROJECT_MEMORY.md`): the draft medical candidate
  may be activated only in local testing or a controlled private beta via a deliberate
  activation mechanism that is disabled in public production. That mechanism is **not** v0.3
  scope, but v0.3 code must not weaken `assertV02ProductionPack` or any production gate.
- v0.3 stores nothing server-side and nothing across reloads. "Real data" (consented,
  de-identified learner recordings and corrected transcripts) is a controlled-beta concept
  governed by the policy above; v0.3 code makes that future collection possible only by keeping
  audio and transcripts strictly local and export-free by default.

## 10. UI behavior

- Permission primer → record indicator during speaking (visible + announced, not color-only) →
  playback bar on the attempt-complete screen → processing view with progress and cancel →
  transcript editor → review panel.
- Delivery observations render in their own panel, visually and verbally separate from anything
  content-related; a one-line "what this measures / what it doesn't" note ships with the panel.
- Every failure row of the §5 matrix has written copy and a working typed/self-review path.
- Unsupported-device and low-memory fallbacks are explicit UI states, not silent degradation.

## 11. Accessibility baseline

Everything from v0.2 §10 still applies, plus:

- The no-audio path is a first-class equal path, not an error state.
- Recording/processing status is announced via the existing polite live region; no
  audio-only signaling.
- Transcript editor fully keyboard-operable; uncertain-span highlights have non-color encoding.
- Processing view announces progress and completion; cancel is focusable and operable.
- Reduced-motion: ring/progress animations respect `prefers-reduced-motion` as in v0.2.

## 12. Offline, caching, and hosting

- App shell behavior unchanged (v0.2 service worker, network-first nav, cache-first hashed
  assets, owned-prefix cleanup).
- Model artifacts are cached only after explicit activation, versioned by pinned hash, and
  evictable without breaking the shell; download interrupted/offline → §5 matrix row.
- Transcription must work fully offline once the model is cached (that is the point of local
  STT); the offline e2e spec gains a cached-model transcription case.

## 13. Security and privacy baseline

Browser policy:

- **No raw audio leaves the browser** — verified by tests and by the exit-gate device audit.
- CSP stays `default-src 'self'`; no remote code, fonts, or analytics. Whisper runtimes need
  WebAssembly: decide explicitly between adding a scoped `wasm-unsafe-eval` to `script-src`
  (documented, minimal) and a runtime build that needs no eval. No `unsafe-eval`.
- Model artifacts are pinned and integrity-checked (hash recorded with the model version);
  microphone streams are never cloned, forwarded, or stored beyond the playback lifetime in §6.
- MediaRecorder output and transcripts are rendered as inert text only.

Repository and CI policy (unchanged from v0.2, restated for the new dependency surface):

- Any new dependency (STT runtime, audio utils) must be justified, pinned, and pass the existing
  dependency-review job; CI actions remain SHA-pinned; frozen lockfile; no `pull_request_target`.
- The candidate lane and build gates stay intact: candidate JSON never enters `dist/`
  (`validate-build.mjs` already forbids it — keep that assertion working).

## 14. Tests and exit gate

Tests:

- Unit: VAD, pause detection, clipping, loudness variation, WPM, filler/repetition matchers over
  synthetic PCM fixtures and fixed transcripts; decode failure paths; reducer transitions for
  every §5 row; worker protocol (progress/cancel/stale/timeout/memory/pinned-version).
- Component: primer, record indicator, playback, processing view, transcript editor
  (edit/approve/highlight), delivery panel, all fallback states.
- a11y suite extended for the new surfaces; existing v0.2 suites run unchanged.
- e2e: offline shell regression; cached-model offline transcription.

Exit gate (all required):

1. Representative Android, desktop, and low/mid-range device tests complete without UI freezes.
2. Benchmark data for on-device transcription is published in the repo (device, model tier,
   latency, memory, accuracy observations).
3. No raw audio leaves the browser (audited on the device matrix).
4. Speech metrics deterministic within documented tolerances.
5. Full pre-existing pipeline green: lint, typecheck, `content:validate` (including
   `candidate:check`), unit + a11y tests, build + `validate-build`.

## 15. Coding and review rules

Carried over from v0.2 §14: pure domain logic with injected dependencies (clock, randomness,
audio devices, worker); no new abstraction without a second caller; no feature flags where a
state transition works; comments only for non-obvious constraints; every failure path has copy +
test; the reviewer must not have to add tests. TypeScript strict + `verbatimModuleSyntax`;
service-worker and worker code excluded from the app tsconfig like `src/sw`.

## 16. Open decisions (discover before asking)

1. **STT runtime**: transformers.js vs whisper.cpp WASM build — evaluate against the benchmark
   plan; choose on measured latency/memory on the target phone, not on reputation.
2. **Model tier go/no-go**: `base.en` is the candidate default. If too slow/large on the target
   phone, test `tiny`/`base` tiers or make transcription optional. Decision is made from the
   v0.3 benchmark on representative Indian-English medical speech, per the adjusted decision in
   EXECUTION_PLAN — third-party WER figures are never encoded as product guarantees.
3. **WASM CSP**: scoped `wasm-unsafe-eval` vs no-eval runtime build (§13).
4. **Model storage budget**: cache quota for the pinned model on low-storage phones; eviction
   and re-download behavior.
5. **Benchmark corpus**: assemble consented, de-identified representative speech before
   implementation locks the model tier (per PROJECT_MEMORY toolchain note).

### Resolutions (as implemented, 2026-08-31)

1. **STT runtime → transformers.js 3.7.6** (`@huggingface/transformers`), pinned. whisper.cpp
   would have meant maintaining a custom WASM build; transformers.js ships the pinned ORT
   runtime, runs whisper-base.en quantized (q4) single-threaded on WASM, and its browser cache
   gives offline transcription after first activation. The benchmark plan (item 2/5) is
   unchanged: base.en stays the *candidate* default and the tier decision still waits on the
   representative-speech benchmark — the code treats transcription as optional, so the
   implementation does not lock the tier.
2. **WASM CSP → scoped `wasm-unsafe-eval`** (§13). `script-src 'self' 'wasm-unsafe-eval'`
   permits WebAssembly compilation only; JS eval stays forbidden and
   `scripts/validate-build.mjs` fails the build if any shipped `.js` contains `eval(` or
   `new Function(`.
3. **Playback-bar placement**: §5 is taken literally — `RECORDING_READY` auto-transitions
   ATTEMPT_COMPLETE → PROCESSING, so ATTEMPT_COMPLETE remains the no-audio rest state. The
   playback bar renders on PROCESSING, SELF_REVIEW, and REVIEW wherever a clip exists, which
   preserves §10's "listen before you review" intent without a second rest state.
4. **Analysis failure → typed path, no new event types**. When decode/analysis throws, the
   orchestrator dispatches `START_TYPED_REVIEW` and sets the `AudioErrorCode` for copy; the
   typed/self-review path is the universal fallback per §5's error matrix.
5. **Cancel during transcription = typed path**. The cancel button dispatches the same
   `startTypedReview` action (reducer emits `CANCEL_TRANSCRIPTION`), landing in SELF_REVIEW
   with a null issue — cancelling is a choice, not an error.
6. **Model storage budget**: the ORT wasm runtime (~21.6 MB, same-origin under `models/ort/`)
   is runtime-cached by the service worker under a 32 MB cap on first explicit activation;
   model weights live in transformers.js's own CacheStorage (`transformers-cache`), which SW
   cleanup never touches. Eviction/re-download on quota pressure is deferred to the benchmark
   work on the target phone.
