# MediPrompt v0.4 Development Context — Content Coverage

Status: build brief for v0.4. Consolidates the v0.4 scope into one executable contract, the same
way `V0.3_DEVELOPMENT_CONTEXT.md` did for private speech intelligence.
Base: `develop` at PR #16 (v0.3 physiotherapy practice beta, merged to main via PR #17).
Branch: `feature/v0.4-content-coverage`.

This brief is the single source of truth for v0.4 implementation. If code and this brief disagree,
the brief wins until it is amended.

## 1. What v0.4 is

v0.4 turns the approved transcript into *content feedback*, entirely on-device and without a model
download:

- **Content coverage** against the variant rubric: for each rubric concept, test whether the
  learner's approved transcript expresses one of the concept's `acceptedPhrases`.
- A **single actionable prescription** per attempt — the highest-weight missed concept, named as the
  next thing to address. Not a dashboard.
- A **"not verifiable from sources" fallback** when a topic has no source-grounded rubric, instead of
  a fabricated grade.
- Coverage is shown on the review screen, **visually and verbally separate from delivery** (v0.3's
  `DeliveryPanel`). Content and delivery never collapse into one score.

The v0.3 loop (mic → record → transcribe → approve) is unchanged. v0.4 only adds what happens to the
approved text: a deterministic coverage pass and one prescription line.

## 2. What is explicitly excluded

- **Semantic cosine / embedding models** (`all-MiniLM-L6-v2`): v0.5. v0.4 ships a deterministic
  lexical engine so coverage is zero-cost, offline, and CI-deterministic — no model download, no
  WASM, no async pipeline. The lexical engine is the guaranteed baseline that always runs; the
  semantic engine will be an optional enhancer on top of it.
- **Correctness grading.** Coverage is "did the expected idea appear", not "is the answer right".
  No medical-correctness score, no confidence, no emotion (L1 non-goals, unchanged from v0.3).
- **Gap Score (attempt2 − attempt1 delta).** v0.5. v0.4 has no second attempt yet.
- **Scoring before transcript approval.** Coverage runs only on an approved/typed transcript, never
  on the raw machine draft.
- Accounts, backend, server storage: still out.

## 3. The coverage engine

`src/scoring/coverage.ts` — pure, deterministic, no I/O.

- `scoreCoverage(transcript, concepts): CoverageReport`.
- Normalization: lowercase, strip non-alphanumeric, collapse whitespace. Stopwords
  (`a/an/the/and/of/to/...`) are dropped from phrase token logic so a phrase of glue words cannot
  auto-hit.
- A phrase is present when its normalized form appears as a substring **or** every significant token
  appears in the transcript token set. The token path catches word-order drift and minor Whisper
  errors on accented speech; the substring path catches tight multi-word terms.
- A concept hits when **any** of its `acceptedPhrases` hits.
- `CoverageReport` carries per-concept `ConceptResult` (hit + matchedPhrase for evidence),
  `hitCount/totalCount`, a weighted fraction, and a flat fraction. `verifiable` is false only when
  the rubric has zero concepts → the not-verifiable fallback.

Domain shapes (`ConceptResult`, `CoverageReport`) live in `src/practice/types.ts` so `practice/`
does not depend on the scoring module; `coverage.ts` imports them.

## 4. The prescription

`src/scoring/prescription.ts` — `prescribe(report): Prescription`.

- `ACTION`: name the highest-weight missed concept (ties break by rubric order, so the choice is
  stable for a given report). Copy: `Next attempt: address "<label>".`.
- `FULL`: every concept touched → reinforce ("tighten your timing or try a harder variant").
- `NOT_VERIFIABLE`: empty rubric → "content coverage was not scored; focus on structure and
  delivery instead."

One line. Always one line. The review screen never shows more than one recommended action.

## 5. State-machine + orchestrator changes

- `REVIEW` state gains `coverage: CoverageReport`.
- `TRANSCRIPT_APPROVED` and `SELF_REVIEW_DONE` events gain a `coverage` payload.
- Coverage is computed in `usePracticeSession` (`approveTranscript`, `submitSelfReview`) via
  `findRubric(pack, topicRef)` + `scoreCoverage(text, rubric.concepts)`, mirroring how `textMetrics`
  is computed in the orchestrator (the reducer stays pure — it only threads the payload through).
- `findRubric` added to `src/content/packQuery.ts`: resolves the rubric by `rubricId` within the
  topic that owns the drawn variant; returns `undefined` when absent (the not-verifiable path).

No new commands, no new async states, no new worker. The v0.3 post-attempt states are unchanged.

## 6. UI

`src/components/CoveragePanel.tsx` — rendered inside `AttemptReview`, above `DeliveryPanel`.

- Heading "Content coverage"; a one-line "what this measures" note (coverage, not correctness).
- Score line (`aria-live="polite"`): "You touched X of N listed concepts (P% by weight)."
- The single prescription in a distinct treatment.
- "Concepts not yet touched" list (missed labels); "Concepts you touched" behind a `<details>`.
- When not verifiable: only the fallback line, no score.
- Separate from `DeliveryPanel` by heading and copy; content and delivery are never merged.

`AttemptReview` accepts a `coverage` prop; `App.tsx` passes `s.coverage` from the `REVIEW` state.

## 7. Content

No schema change — `Concept` with `acceptedPhrases` already exists. The public practice-beta pack
(the 20-topic MPT cardiorespiratory DRAFT) already carries 138 source-grounded concepts with
multi-phrase `acceptedPhrases`, so coverage scores against real rubrics on day one. The non-medical
interaction fixture (test-only, never shipped) likewise carries concepts for unit fixtures.

## 9. Budget and build gate

No new runtime assets (no model, no WASM). `validate-build.mjs` is unchanged. The shell budget
(1.5 MiB) and entry-JS budget (512 KiB) are respected; the added scoring + panel modules are a few
KiB of pure TS. CSP (`wasm-unsafe-eval` scoped, no `unsafe-inline`/`eval`) is unaffected — coverage
is pure JS with no dynamic code construction.

## 10. Exit gate (unchanged from v0.3 + this addition)

- No raw audio leaves the browser. (unchanged)
- No score is shown before transcript approval. (unchanged; coverage runs on approval only)
- Coverage is never a correctness grade and never claims medical veracity. (v0.4 addition)
- The not-verifiable fallback is mandatory for any topic without a source-grounded rubric; the app
  must never fabricate a coverage number. (v0.4 addition)
