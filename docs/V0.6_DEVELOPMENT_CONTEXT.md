# MediPrompt v0.6 Development Context — Viva Defense Ladder

Status: implemented on `feature/v0.6-viva-round` in PR #21, reviewed against the
v0.6 exit gate on 2026-09-02. Base: `develop` after v0.5.

This file is the executable v0.6 contract. v0.6 adds an opt-in oral **viva** to a
completed attempt without altering the v0.2–v0.5 loop or its scoring.

## 1. Outcome

After reviewing a completed attempt, the learner can opt into a viva: the examiner
asks a sequence of follow-up questions climbing a ladder
Recall → Explain → Apply → Differentiate → Defend. Each follow-up is answered
aloud, transcribed on-device, approved, then coverage-scored against only that
follow-up's target rubric concepts. A viva summary aggregates defense coverage
across all follow-ups.

- Viva is **opt-in from REVIEW** via "Begin viva", shown only when the topic has
  usable viva questions. A topic without them shows an explicit "viva unavailable"
  reason; the feature is never silently hidden.
- Viva coverage is **separate from the main attempt coverage** and never feeds
  Refinement Delta (a different construct).
- The v0.4 lexical engine and v0.5 semantic engine are reused unchanged; viva
  calls `scoreCoverage` with the follow-up's filtered target concepts. Semantic
  refinement is gated and non-blocking; lexical always runs first.
- Each follow-up answer gets its own attemptId; transcripts are session-local,
  bounded, never uploaded. The same approval gate applies: no coverage before
  transcript approval.
- Viva answers are recorded in a session-local answer trace (`VivaRuntime.answers`,
  bounded at 19), not in the main attempt history, so the main review stays clean.

## 2. Explicit exclusions

- Medical correctness, confidence, emotion, accent, competence, or long-term-learning inference.
- Refinement Delta for viva answers (different construct; deferred).
- Persistent history, accounts, backend storage, analytics, or transcript upload.
- Spaced resurfacing / exam-countdown (v0.7).
- PDF authoring / build-your-own packs (v0.8) and connected provider coaching (v1.1+).
- Semantic-to-numeric promotion before educator-labelled calibration (unchanged from v0.5).

## 3. Viva state machine

The viva states are separate from the v0.2–v0.5 states so the main loop is
untouched. Async results are stale-dropped by the current viva answer's
attemptId. `attempt` is the in-flight defense answer, so the shared
recorder/transcription pipeline keys off it unchanged.

`REVIEW → START_VIVA → VIVA_READY → BEGIN_VIVA_QUESTION → VIVA_ASKING
→ START_VIVA_SPEAKING → VIVA_SPEAKING → (TIMER_ELAPSED | CLOSE_TIMER)
→ VIVA_ATTEMPT_COMPLETE → (RECORDING_READY → VIVA_PROCESSING
   → METRICS_READY/TRANSCRIPT_READY → VIVA_TRANSCRIPT_REVIEW
   | START_TYPED_REVIEW → VIVA_SELF_REVIEW)
→ (APPROVE_VIVA_TRANSCRIPT | VIVA_SELF_REVIEW_DONE) → VIVA_ANSWER_REVIEW
→ NEXT_VIVA_QUESTION → (VIVA_ASKING | VIVA_COMPLETE)
→ EXIT_VIVA → REVIEW (base restored)`

`EXIT_VIVA` is available from any viva state; it restores the captured base
`REVIEW` state (main attempt coverage preserved) and emits
`REVOKE_RECORDING`/`CANCEL_TRANSCRIPTION` for the in-flight viva answer.
`CHANGE_SELECTION` and `SPIN_AGAIN` from a viva state clean up the viva recording
and return to `IDLE`/`DRAWING`. The viva speaking window is `VIVA_SPEAKING_SECONDS`
(120 s), shorter than the main attempt.

`VivaRuntime = { requestId, questions, index, answers, base }` where `base` is the
captured `REVIEW` state. `VivaAnswer` records question, attemptId, transcript,
coverage, textMetrics, metrics. `VIVA_COMPLETE` carries a frozen `VivaSummary`
computed purely from the answers by the reducer.

## 4. Scoring

`src/scoring/vivaSummary.ts` aggregates completed answers:

- `weightedFraction` = Σ(weightedHit) / Σ(weightedTotal) over verifiable answers,
  where each follow-up is weighted by the total weight of its target concepts.
- Not-verifiable answers are excluded from the numeric aggregate and counted in
  `notVerifiableCount`; they never become a fabricated 0%.
- `perFollowUp` carries `{ questionId, level, coverage }` for transparent display.

Coverage per answer is `scoreCoverage(transcript, targetConcepts)` where
`targetConcepts` is the variant rubric filtered to the question's
`targetConceptIds`. The prescription engine is reused per answer. Viva coverage
is "did the expected idea appear in this defense answer", not a correctness grade.

## 5. Content schema

`VivaQuestion = { id, level: RECALL|EXPLAIN|APPLY|DIFFERENTIATE|DEFEND, prompt,
targetConceptIds }`. `Topic.vivaQuestions?` is optional. The schema
(`content/schema/topic-pack.schema.json`) validates structure; `packValidator`
adds a cross-reference check that every `targetConceptIds` resolves to a concept
in some rubric of the same topic, and that question ids are unique within a topic.
`packQuery.vivaQuestionsFor` further filters at snapshot time to questions whose
targets all exist in the **variant's** rubric, so viva is only offered when its
targets are scorable for the drawn variant.

The 20-topic MPT cardiorespiratory DRAFT pack authors viva questions on four
topics (cardiac-rehabilitation, copd-assessment-planning, pulmonary-rehabilitation,
cardiovascular-assessment-ecg), each covering 2–3 ladder levels. Follow-ups are
source-grounded to the same rubric concepts — no new clinical claims.

## 6. UI contract

- `AttemptReview` shows "Begin viva" with the question count when viva is
  available; otherwise an explicit "viva unavailable" note.
- `VivaOverview` lists the ladder and offers Begin / Back to attempt review.
- `VivaQuestionCard` shows the level badge, prompt, Start speaking, and Exit viva.
- `VIVA_SPEAKING` reuses the countdown ring; `VIVA_ATTEMPT_COMPLETE` mirrors the
  main complete screen; `VIVA_PROCESSING`/`VIVA_TRANSCRIPT_REVIEW`/`VIVA_SELF_REVIEW`
  reuse `ProcessingView`/`TranscriptEditor`/`SelfReview` with viva handlers.
- `VivaAnswerReview` shows the question, approved transcript, coverage against
  targets, delivery, and Next question / Finish viva / Exit viva.
- `VivaSummary` shows the aggregate percentage, per-follow-up rows, and the
  not-verifiable count; "Back to attempt review" returns to the main REVIEW.
- All model/content text renders as inert React text. a11y: headings, aria-live
  status, focus management on each viva screen via `FOCUS_VIEW` targets
  (`viva-asking`, `viva-processing`, `viva-review`, `viva-complete`).

## 8. Release boundary

The 20-topic MPT pack remains a source-linked **unreviewed draft**. v0.6 is
suitable for public practice-beta testing, not a medically approved release.
Viva coverage is not a grade. Qualified educator attestation of the exact prompts,
rubrics, accepted phrases, and semantic calibration set remains mandatory before
semantic evidence can alter numeric coverage or the beta can claim medical
approval. Semantic-to-numeric promotion stays locked behind a future
educator-labelled calibration that lowers and versions the covered threshold.
