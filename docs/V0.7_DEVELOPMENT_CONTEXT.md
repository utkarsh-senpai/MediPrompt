# MediPrompt v0.7 Development Context — Private Learning Plan

**Status:** implemented and review-hardened on `feature/v0.7-spaced-resurfacing`

**Base:** `develop` after v0.6

**Release:** static GitHub Pages PWA; no account or backend

This is the executable v0.7 contract. It supersedes the earlier plan that assigned v0.7 to the
Java content compiler; that compiler moves to v0.8. The rebaseline is deliberate because the
opened v0.7 branch implements the next learner-value step: returning to weak topics at the right
time.

## 1. Learner outcome

The basic mode/subject → spin → timer loop remains unchanged and works with storage disabled. A
learner may explicitly enable **Private learning plan** in Settings. After a main attempt reaches
review, MediPrompt then:

1. saves a privacy-minimized attempt summary on the device;
2. maps verifiable aggregate coverage to a bounded SM-2-style schedule;
3. shows how many topics are due and opens the exact next due prompt;
4. optionally prioritizes weak due topics during the 14 days before an exam; and
5. lets the learner export or verifiably delete all saved learning-plan data.

An unverifiable attempt may be retained as an attempt summary but has `schedule: null` and does not
advance or reset spacing. The plan is a practice organizer, not a grade, competence claim, or
medical-correctness assessment.

## 2. Consent and data boundary

Persistence is **off by default**. Enabling it is an explicit settings action. Disabling it pauses
future writes without silently deleting existing data; the Learning plan surface remains reachable
for export and deletion.

`AttemptRecord` may contain only:

- schema and attempt identity;
- pack/subject/topic/variant/prompt/rubric identity;
- practice mode, challenge, and attempt number;
- reviewed timestamp;
- aggregate hit/total/fraction values plus scoring identity; and
- spaced-schedule state or `null`.

It must never contain raw audio, playback blobs, transcript text, the original machine transcript,
concept-level results, semantic transcript segments, patient information, or model embeddings. The
export uses the same minimal record and states this boundary in the file. No data is uploaded.

Retention is capped at the newest 500 attempts. Delete-all clears IndexedDB and the optional exam
date, reloads the store, and reports success only after zero records are observed. Storage errors
are visible; they never interrupt the current review or the timer-only loop.

## 3. Store and validation contract

`src/platform/historyStore.ts` provides `IndexedDbHistoryStore` and
`InMemoryHistoryStore` behind `HistoryStore`.

- Database: `mediprompt-history`, version 2; store `records`, key `attemptId`.
- Index: materialized `topicFingerprint`, validated to equal
  `topicFingerprint(topicRef)` before every write and after every read.
- Version 2 deletes the unreleased v1 store instead of migrating it because v1 could contain full
  transcript text and its index field was absent.
- IndexedDB-open failure falls back to bounded memory for the session. Transaction failures reject
  and are surfaced rather than being reported as successful persistence/deletion.
- Appends reject malformed input. Reads drop malformed or unknown-schema records.
- Validation is exact-key and recursive across the stored nested structures. It bounds identifiers,
  counts, fractions, easiness, repetitions, intervals, and dates; checks hit/total/fraction
  consistency; rejects dangerous prototype keys; and requires schedule/verifiability agreement.
- Returned and stored objects are deep clones. Reusing an `attemptId` replaces the existing record.

Real adapter tests use `fake-indexeddb`; the suite exercises the actual object store and topic index,
not only the no-IndexedDB fallback.

## 4. Scheduling contract

`src/practice/spacedRepetition.ts` is deterministic apart from its injected review time.

- A topic fingerprint includes pack id/version, subject, topic, and variant.
- Coverage bands map to recall quality 0–5: `>= .9 → 5`, `>= .75 → 4`, `>= .5 → 3`,
  `>= .25 → 2`, `> 0 → 1`, otherwise `0`. Unverifiable coverage maps to `null`.
- Quality below 3 resets successful repetitions and uses the first interval. Otherwise the SM-2
  easiness recurrence is clamped at 1.3; default intervals are one day then three days.
- Due dates are strict learner-local `YYYY-MM-DD` calendar dates. Arithmetic does not turn local
  dates into UTC instants, avoiding midnight/timezone shifts.
- The queue uses the latest scheduled record per topic, splits due and upcoming, and sorts by
  overdue/soonest date.

`src/practice/examCountdown.ts` accepts only a real `YYYY-MM-DD` calendar date. An exam 0–14 days
away triages due topics by weakest aggregate coverage, breaking ties by overdue date. A missing,
invalid, past, or more distant exam keeps most-overdue-first ordering.

## 5. UI and orchestration

- `SettingsDialog` owns the explicit persistence opt-in and explains the exact data boundary.
- `usePracticeSession` writes only after `REVIEW`, never after recording or an unapproved draft.
- `LearningPlan` is a compact collapsed surface on the idle screen. It shows due state, opens the
  exact current-pack variant, saves the optional exam date, exports JSON, and uses two-step verified
  deletion.
- A saved reference is revalidated against current pack, topic, prompt, rubric, difficulty, and
  variant identity before it can be opened. Stale pack references remain exportable/deletable but
  cannot launch an unrelated prompt.
- Review reports saving, saved, or failure truthfully and explicitly confirms that no transcript was
  stored.

## 6. Security, privacy, and failure invariants

- No invisible persistence and no upload path.
- No transcript-derived excerpts in IndexedDB or export.
- No arbitrary timestamp parsing for exam/due dates.
- A past exam cannot activate cram sorting.
- Bounded record count and bounded field sizes limit accidental storage growth.
- Malformed writes fail closed; corrupt reads never become executable UI content.
- Storage denial, private browsing, quota failure, or corruption cannot block practice.
- Initial JavaScript remains under 512 KiB uncompressed. The content pack is dynamically imported
  as a fallback chunk (not bundled into the entry) so the strict 512 KiB initial-entry budget holds.
  The precached shell budget is widened to 2,560 KiB to carry the 265-topic pack file plus its
  fallback chunk alongside the reused model worker; model runtimes remain outside that shell budget.
- The medical pack remains an unreviewed draft with its existing educational-use warning.

## 7. Verification gate

Before promotion, all of the following must pass from this branch:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:a11y
pnpm content:validate
pnpm build
pnpm test:e2e
pnpm audit --prod
pnpm audit
git diff --check origin/develop...HEAD
```

Tests cover strict record/date parsing, privacy-field rejection, deep-copy semantics, replacement,
retention, real IndexedDB topic lookup/clear, memory fallback, schedule recurrence, local-calendar
dates, past-exam behavior, settings opt-in, review-time persistence without transcript data, exact
resurfaced-topic launch, and application accessibility.

## 8. Explicit exclusions

- Persisted transcripts or audio.
- Cross-device sync, accounts, analytics, or a backend.
- Import/merge of exported history; export is portability/recovery evidence only in v0.7.
- Claims that spacing or coverage proves medical knowledge, correctness, or competence.
- Changing semantic evidence from non-counting to numeric without educator-labelled calibration.
- Medical-content approval; qualified educator attestation remains a later release gate.

## 9. Content expansion — 265 curriculum topics

v0.7 also expands the public practice pack from 20 cardiorespiratory topics to the full 265-topic
MPT competency-based curriculum across all eight app-subjects (the curriculum's seven subjects, with
Cardiovascular & Respiratory shipped as two app-subjects to preserve existing subject identity):
Research Methods & Bioethics (32), Applied Physiotherapeutics (35), Musculoskeletal (50), Neuro
(35), Respiratory (13), Cardiovascular (13), Community Health (53), Sports (34).

**Neuro Physiotherapy is the emphasis.** 16 of its 35 topics are fully authored with rubrics,
concepts, accepted phrases, fictional cases, follow-ups, and viva defense-ladder questions grounded
in verified 2025-26 sources (AHA/ASA 2016 stroke rehabilitation guideline; NICE NG236 stroke, NG62
cerebral palsy, NG71 Parkinson's; Cochrane CIMT, mirror therapy, virtual reality, treadmill/BWS;
GMFM; GMFCS; Fugl-Meyer; Berg Balance; MMSE; ASIA ISNCSCI 9th ed.; DMD and SMA care standards).
Four flagship neuro topics (stroke, cerebral palsy, DMD/SMA, Parkinson's) carry full challenge
trios and viva ladders. Sources were fetch-verified; no citation was fabricated. Neuro topics for
which no current fetch-verified source exists (classic technique textbooks, embryology,
reflexes, motor-learning theory, etc.) are scaffolded rather than cited.

**Scaffolded topics** (the remaining ~19 neuro topics and all of the other seven subjects) carry one
GUIDED variant and a rubric with zero concepts, so coverage falls back to "not verifiable from
sources" — playable for speaking practice, but not content-scored until authored. The schema was
loosened (`rubric.concepts` `minItems` 1 → 0) to permit this staged authoring, and the
`assertV02ProductionPack` attestation gate now rejects empty-concept rubrics, so scaffolded topics
cannot be promoted to APPROVED (attested) unchanged. The draft warning stays on every screen until
educator attestation.

The pack file is minified to 413 KiB (under the 512 KiB pack-byte budget) and loaded via a dynamic
fallback chunk so the entry JS stays under 512 KiB. `MAX_SCAN_NODES` was raised 10,000 → 50,000 to
accommodate the larger pack. The `practiceHistory` opt-in, scheduling, and the 265-topic expansion
are independent: the loop and scoring are unchanged, and the expansion ships no new clinical claims
beyond the verified-source neuro content.
