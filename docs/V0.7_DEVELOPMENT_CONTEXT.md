# MediPrompt v0.7 Development Context — Persisted History & Spaced Resurfacing

Status: implemented on `feature/v0.7-spaced-resurfacing` in PR (this file). Base:
`develop` after v0.6.

This file is the executable v0.7 contract. v0.7 introduces the first
**persisted-history** layer: completed, reviewed attempts are summarized and stored
locally, and a pure spaced-resurfacing scheduler derives a review queue from that
history, triaged by an optional exam countdown. The v0.2–v0.6 practice loop and
its scoring are untouched.

## 1. Outcome

After a reviewed attempt, the attempt is summarized into an `AttemptRecord` and
appended to a local `HistoryStore`. From the accumulated history, a pure
`buildResurfacingQueue` derives the set of topics due for resurfacing (overdue or
due today) and upcoming topics. An optional exam date reorders the due set: far
from the exam, the most overdue topics come first; inside a cram window, the
weakest-covered due topics come first so limited time targets the gaps most
likely to cost marks.

- Persistence is **local-only** (`IndexedDB`, with an in-memory fallback). Nothing
  is uploaded. The v0.2–v0.6 privacy model (transcripts session-local, never
  uploaded) is preserved: the approved transcript text is stored on-device to
  power future review, never transmitted.
- Scheduling is an **SM-2 variant** tuned for short daily practice cadence
  (configurable first/second intervals; default 1 day, then 3 days).
- Coverage drives scheduling via a coverage→quality map. **Not-verifiable**
  attempts carry no scorable signal and must not advance scheduling.
- The state machine, reducer, and UI from v0.2–v0.6 are **unchanged** in v0.7.
  UI consumption of the queue (a "resurfacing" surface and exam-date setting) is
  deferred to a v0.7 follow-up so this PR lands the persistence and scheduling
  foundation with full tests and no regression risk to the practice loop.

## 2. Explicit exclusions

- Accounts, backend storage, analytics, or transcript upload.
- Medical correctness, competence, or long-term-learning inference.
- Changing the v0.2–v0.6 reducer, state machine, or scoring.
- A resurfacing UI surface and the exam-date settings control (v0.7 follow-up).
- PDF authoring / build-your-own packs (v0.8) and connected provider coaching (v1.1+).
- Semantic-to-numeric promotion before educator-labelled calibration (unchanged).

## 3. Persisted-history store

`src/platform/historyStore.ts` exports `IndexedDbHistoryStore` and
`InMemoryHistoryStore`, both implementing the `HistoryStore` port
(`src/practice/types.ts`). IndexedDB is async, so the interface is async.

- Database `mediprompt-history`, version 1, object store `records` keyed by
  `attemptId`, indexed by `topicFingerprint` (see `spacedRepetition.topicFingerprint`).
- `IndexedDbHistoryStore` degrades to its `InMemoryHistoryStore` when IndexedDB
  cannot be opened (private mode, SSR, tests). Reads and writes are mirrored into
  the memory fallback so a later failed read still sees appended records.
- Stored records are **untrusted**. `parseAttemptRecord` validates the schema
  version, every `TopicRef` field, mode/challenge enums, `attemptIndex ≥ 1`, a
  parseable `reviewedAt`, a structurally valid `CoverageReport` (scoring method,
  finite bounded fractions, valid `unavailableReason`), a finite clamped
  `SpacedSchedule` with a parseable `nextDueAt`, and rejects dangerous
  prototype keys (`__proto__`, `prototype`, `constructor`). Malformed records are
  dropped on read; `append` normalizes through the same parser.

## 4. Spaced-resurfacing scheduler

`src/practice/spacedRepetition.ts` is pure (history and the wall clock are
injected).

- `topicFingerprint(ref)` — stable per-topic identity (`packId`, `packVersion`,
  `subjectId`, `topicId`, `variantId`).
- `coverageToQuality(report)` — maps a verifiable `CoverageReport` to an SM-2
  recall quality 0..5 by `weightedFraction` bands (≥0.9→5, ≥0.75→4, ≥0.5→3,
  ≥0.25→2, >0→1, 0→0). Returns `null` for not-verifiable reports.
- `scheduleReview(prev, quality, reviewedAtDate, config)` — SM-2 recurrence:
  quality < 3 resets (`repetitions = 0`, interval = `firstIntervalDays`);
  otherwise EF' = EF + (0.1 − (5−q)(0.08 + (5−q)·0.02)) clamped to
  `minEasiness`, `repetitions += 1`, interval = `firstIntervalDays` |
  `secondIntervalDays` | `round(prevInterval · EF)`. The next due date is
  anchored to the **review day** (UTC day start + interval), not the prior due
  date, so a late review does not stack intervals.
- `latestRecord(records)` — the record with the greatest `reviewedAt`.
- `buildResurfacingQueue(records, now, neverAttempted?)` — one item per topic
  (its latest record), split into `due` (overdue, most overdue first) and
  `upcoming` (soonest first); `neverAttempted` topics are passed through minus
  those already attempted.

`DEFAULT_SR_CONFIG`: `minEasiness 1.3`, `initialEasiness 2.5`,
`firstIntervalDays 1`, `secondIntervalDays 3`.

## 5. Exam-countdown triage

`src/practice/examCountdown.ts` is pure.

- `daysUntilExam(examAt, now)` — whole days to the exam day (negative past);
  `null` when unset or unparseable.
- `examTriage(queue, examAt, now)` — reorders `queue.due`: inside
  `CRAM_WINDOW_DAYS` (14) of the exam, weakest coverage (`weightedFraction`)
  first; otherwise most overdue first. Ties break by overdue order. `upcoming`
  and `neverAttempted` are returned unchanged.
- `parseExamSchedule(raw)` — validates an `ExamSchedule` payload (`schemaVersion`
  1, `examAt` null or parseable ISO, dangerous keys rejected).

## 8. Release boundary

The 20-topic MPT pack remains a source-linked **unreviewed draft**. v0.7 adds
local persistence and scheduling only; it is suitable for public practice-beta
testing, not a medically approved release. Spaced resurfacing is a study aid,
not a competence measure. Qualified educator attestation of the exact prompts,
rubrics, accepted phrases, and semantic calibration set remains mandatory before
semantic evidence can alter numeric coverage or the beta can claim medical
approval.
