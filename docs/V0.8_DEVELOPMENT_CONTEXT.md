## 2. Subject identity migration

The runtime now uses one subject ID and title matching the curriculum structure:

```text
cardiovascular-and-respiratory-physiotherapy
Cardiovascular & Respiratory Physiotherapy
```

The 13 Respiratory and 13 Cardiovascular topic definitions are composed into that subject. Their
prompt/rubric semantics remain unchanged. Tests, availability gates, offline artifacts, and saved
topic lookup use the combined identity. No legacy split subject is accepted by the public-draft
contract.

## 3. Sports curriculum completeness

Sports contains all 20 Paper III and 14 Paper IV candidate labels in
`docs/curriculum/MPT-CBC-topics.md`. v0.8 does not drop curriculum topics merely because a recent
guideline does not teach a foundational concept. Each active topic instead uses the best fitting
source class and states its limits:

- 2025-26 consensus/guidance for WADA, athlete mental health, female-athlete injury prevention,
  exercise prescription, and current rules;
- current official federation portals for cricket, football, basketball, hockey, tennis,
  athletics, and aquatic-sport rules;
- peer-reviewed consensus/reviews for concussion, surveillance, REDs, injury psychology,
  return-to-sport, and manual-therapy mechanisms;
- recognized foundational texts for sport science, biomechanics, and curricular technique names.

Publication year is not a proxy for validity. Older sources are labelled with their real date and
used only within scope. Foundational texts do not override current rules or clinical guidance.
Manual therapy is presented as a consented, reassessed adjunct to active rehabilitation; named
schools are not diagnoses and no specific tissue-release mechanism is asserted. Grief models are
not presented as mandatory linear stages. Mental-health diagnosis and psychotherapy remain outside
ordinary physiotherapy scope and require qualified referral.

## 4. Medical-content state

The generated candidate remains deliberately:

```json
{
  "contentKind": "MEDICAL",
  "review": { "status": "DRAFT", "reviewers": [], "reviewedAt": null }
}
```

All 95 active topics have at least two non-empty, source-linked rubric criteria. The generated
`docs/curriculum/MPT-ACTIVE-SUBJECTS-ATTESTATION.md` contains every active question, criterion,
accepted phrase, citation, and blank reviewer field. It is an unsigned review worksheet, not an
attestation. v0.8 can be software-production-ready and publicly testable only under the persistent
“Curriculum beta · unreviewed draft” boundary. It cannot be described as medically approved.

## 5. Bounded runtime changes

The minified candidate is about 580 KiB. The loader and service worker both enforce the same
640 KiB maximum so the online and offline paths cannot disagree. The source array remains schema
bounded at 96 entries; v0.8 uses 81. Existing nesting, object-scan, identifier, prompt, timer,
artifact, and shell limits remain enforced.

The application package version is `0.8.0`. The candidate version remains `0.3.0` because this is
an activation/content-scope revision within its current runtime schema, not a claim of educator
publication.

## 6. Regression and release gates

The public-draft validators independently require:

- seven exact subject IDs and counts totalling 265;
- exactly the 35/26/34 active split;
- `MEDICAL` + unattested `DRAFT` review state;
- no empty rubric for any active variant;
- enough challenge trios for Explain/Apply/Defend behavior;
- rejection by the approved medical-release gate;
- exclusion of the generic regression fixture from the learner artifact.

Playwright verifies the visible/disabled subject options and the online/offline core loop. Tests
that require a particular topic use a bounded spin helper. Because the production draw is a
non-repeating shuffled bag, the target must appear within the explicit limit; a missing target now
fails with a useful error instead of hanging or being called flaky.

Required evidence before merge:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:a11y
pnpm content:validate
pnpm build
pnpm test:e2e
pnpm audit --prod
pnpm audit
git diff --check
```

Also inspect a production build at desktop, 320 px width, offline reload, and reduced motion. Every
active subject must spin a real curriculum topic and reach timer, review, retry, and optional
learning-plan paths without console errors.
